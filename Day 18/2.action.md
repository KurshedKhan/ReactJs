## 🎬 What is an Action in Redux?

An **Action** is a **plain JavaScript object** that describes **what happened** in your application.

It is the **only way to send data to the Redux store** using `store.dispatch(action)`.

---

## 🧠 Action Structure (Classic Redux)

```js
{
  type: 'INCREMENT',     // (Required) string constant describing the action
  payload: 1             // (Optional) additional data for the reducer
}
```

* `type` — A unique identifier for the action (mandatory).
* `payload` — Optional data (number, object, string, etc.).

---

## 🛠 Example of Manual Action (Classic Redux)

```js
// actions.js
export const increment = () => ({
  type: 'INCREMENT'
});

export const addAmount = (amount) => ({
  type: 'ADD_AMOUNT',
  payload: amount
});
```

---

## 🚀 Dispatching Actions

```js
dispatch(increment());         // No payload
dispatch(addAmount(5));        // With payload
```

---

## ✅ Using Redux Toolkit: Actions are Auto-Created

When you use `createSlice()`, Redux Toolkit **automatically creates actions** for your reducers.

### 🔹 Example: `counterSlice.js`

```js
import { createSlice } from '@reduxjs/toolkit';

const counterSlice = createSlice({
  name: 'counter',
  initialState: { value: 0 },
  reducers: {
    increment: (state) => { state.value += 1 },
    decrement: (state) => { state.value -= 1 },
    addAmount: (state, action) => {
      state.value += action.payload;
    }
  }
});

export const { increment, decrement, addAmount } = counterSlice.actions;
export default counterSlice.reducer;
```

> 🎁 Redux Toolkit creates action types like `counter/increment`, `counter/decrement` behind the scenes.

---

## 🧪 Dispatching RTK Actions in Component

```js
import { useDispatch } from 'react-redux';
import { increment, addAmount } from '../features/counter/counterSlice';

const dispatch = useDispatch();

dispatch(increment());            // No payload
dispatch(addAmount(10));          // With payload
```

## 📊 Action Lifecycle in Async Calls (using `createAsyncThunk`)

Redux Toolkit auto-generates 3 action types for async:

* `fetchUser.pending`
* `fetchUser.fulfilled`
* `fetchUser.rejected`

You use them in `extraReducers` like this:

```js
extraReducers: (builder) => {
  builder
    .addCase(fetchUser.pending, (state) => { state.loading = true })
    .addCase(fetchUser.fulfilled, (state, action) => { state.user = action.payload })
    .addCase(fetchUser.rejected, (state) => { state.error = true });
}
```

## ✅ Summary

| Term          | Meaning                             |
| ------------- | ----------------------------------- |
| `type`        | A string that describes the action  |
| `payload`     | Data you send along with the action |
| `dispatch()`  | Sends an action to the reducer      |
| `createSlice` | Auto-generates actions + reducer    |
